# ChatGPT Pro 任务模板

本模板由 Codex 根据用户的自然语言需求、仓库事实和本地门禁自行填写。不得要求用户补全占位符；只有缺少会改变产品方向、权限或数据边界的信息时才询问用户。

## 首次委派

```markdown
你是本次任务的外部高级工程师。Codex 是总负责人，掌握本地仓库和运行环境，并会独立审查、应用和测试你的交付。

## 背景与目标
<业务背景、当前问题、期望结果>

## 本地基线
- 仓库/模块：<名称>
- HEAD：<commit>
- 工作树：<clean 或 dirty；说明压缩包是否包含未提交文件>
- 关键版本：<语言、框架、依赖和运行环境>

## 架构与边界
- <现有设计和数据流>
- <必须保留的行为>
- <禁止修改的模块、接口或依赖>
- 不引入与目标无关的重构或新依赖。

## 任务范围
- 研究：<需要确认的问题>
- 修改：<允许修改的文件或模块>
- 排除：<不处理的事项>

## 交付物
1. 根因或设计判断，区分事实、推断和假设。
2. 最小且完整的 unified diff；无法用 diff 表达时提供完整文件并列出路径。
3. 每项修改的理由和潜在回归点。
4. 应执行的测试命令、预期结果和额外测试建议。
5. 尚未验证的风险、依赖的外部事实和备选方案。

## 验收标准
- <可观察的功能标准>
- <测试、性能、安全或兼容性标准>

## 约束
- 你不能访问未上传的本地文件、私有仓库、内部服务或真实生产环境。
- 不要声称运行了你无法实际运行的命令、测试、部署或线上验证。
- 不要索取或生成真实凭据，不要建议关闭安全检查。
- 未经明确要求，不提交 Git、不推送、不部署、不迁移数据库。

请先检查上下文是否足以完成任务。只有缺少会改变实现方向的必要信息时才提问；否则直接完成交付。
```

## 缺陷修正

```markdown
本地独立验收未通过。请基于以下证据提供最小且完整的修正，不要重写已通过部分。

## 失败证据
- 命令：`<实际命令>`
- 结果：<退出码、失败测试>
- 日志：
```text
<只保留定位问题所需日志，删除凭据和无关输出>
```

## 定位
- 文件与位置：<path:line>
- 违反的约束/验收标准：<具体条款>
- 实际行为：<观察到的行为>
- 期望行为：<正确行为>

请返回：
1. 修正后的最小 unified diff；
2. 根因说明；
3. 需要重新执行的测试；
4. 本轮仍未验证的风险。
```

## 交付完整性检查

在结束 Pro 对话前确认：

- 所有补丁块都包含文件路径和足够上下文；
- 新文件给出完整内容；
- 依赖或锁文件变化已解释；
- 测试命令与仓库技术栈一致；
- 没有把建议执行的测试描述成已通过；
- 假设、风险和无法访问的环境已明确列出。
